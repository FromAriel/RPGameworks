## Complete M2 state, save, and lifecycle acceptance

The Gallery chest at tile (8,8), stable placement ID `demo:object.gallery.lens-chest`, grants one `demo:item.lens` (Polished lens). `SessionState` owns frozen inventory and placement snapshots above room-scene lifetime. Its transaction validates and aggregates all changes before committing the item count and the chest's declared `opened` fact together. A rejected capacity, stack, item or revision operation changes neither inventory, placement facts nor revision; a repeated claim reports the authored empty-chest message instead of granting again.

The opened frame and interaction reconstruct from the placement fact after real room travel and a room restart. The Gallery plaque independently commits `demo:fact.gallery.plaque-read`, changes to the authored `plaque-read` frame, and resolves its follow-up clue without repeating an action. Boolean fact defaults, conditions, state priority, item and placement checks, and registered actions are validated before generated content replaces the prior pack. Only deliberate Interact actions run in M2; Enter-region and gameplay-producing State-changed reactions are reserved for later packets.

Three fixed manual slots use a version-1 envelope and IndexedDB database `rpgameworks` / store `saveSlots`. Every envelope carries game/compatibility identity, slot/storage revision, a display-only timestamp, an exact checkpoint, inventory, declared facts, and placement deltas—never Phaser objects, UI state, pending work, controller state, or runtime revision. Saving moves the old current revision to `previous` in the same transaction. Loading validates IDs and the checkpoint, constructs a candidate session and room invisibly, and swaps them only after preparation succeeds. Reload still starts fresh gameplay until the player deliberately loads a retained slot.

Save/Load is a skinned Inventory route with keyboard, controller, and pointer navigation. Empty-slot Load is a real disabled control with an adjacent reason, satisfying N1.2. Overwrites, loads, imports, and previous-revision recovery require explicit confirmation. Import is capped at 256 KiB with fatal UTF-8/JSON parsing and complete compatibility/reference validation; export uses deterministic UTF-8 JSON filenames and revokes its temporary URL. If IndexedDB is unavailable, gameplay stays session-only while current-session export and validated import-to-current-session remain usable.

Malformed/current-versus-previous data, wrong games, future/incompatible versions, unknown IDs, invalid values/checkpoints, controlled unavailable/quota/abort failures, stale tabs, and destination preparation failures are distinct rejection paths. Optimistic per-slot revisions preserve the newer writer and refresh stale metadata. Immutable v1 fixtures cover empty, plaque-read, lens-collected, and previous/current progress. The app owns and cancels repository transactions on disposal; active-room, input, session-subscription, conditional-binding, display-object, texture, transition, and pending-save counts are diagnostic.

Menu, I or Escape opens the skinned Inventory during exploration. It provides an empty state plus item name, quantity and description; Settings is an explicit route from Inventory and F2 still opens Debug. Keyboard arrows and the existing controller stick/D-pad move semantic focus, E/Enter or X confirms, and Escape or B returns. Direction repeat is bounded, selection scrolls into view, and held inputs are cleared across movement/modal/settings/reconnect boundaries. Controller preferences migrate from v2 to v3 by preserving every existing assignment and adding Menu on button 9 or the first unoccupied button.

The prior M2.2 candidate **`cf534f912f39e931d7448e9d577f6bee7fe252b7`** passed [run 35437641180](https://github.com/FromAriel/RPGameworks/actions/runs/35437641180).
